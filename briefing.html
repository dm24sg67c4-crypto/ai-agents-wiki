AI Agents 是什麼？

給完全不懂的人的 10 分鐘簡報

資料來源：自建 LLM Wiki（5 篇來源）

聊天機器人 vs. Agent：差在哪？

  • 傳統聊天機器人依預設腳本回應S5.5
  • Agent 能預判需求、主動行動，必要時升級給人類S5.5
  • 只回答一輪的 LLM、簡單聊天機器人，不算 agentS2.2

〔比喻〕聊天機器人像「常見問題機」；agent 像會自己去查系統、把事情辦完的助理。

Agent 是什麼？三家怎麼說

  • OpenAI：獨立代替使用者完成任務的系統S2.1
  • Anthropic：LLM 動態決定自己的流程與工具使用S1.1
  • IBM：能規劃、做決策、使用工具、保留上下文、完成多步驟任務S5.1
  • 共同點：用 LLM 做決策，並透過工具與外部系統互動S2.3

Agent 和 Workflow 不一樣

  • Workflow：LLM 與工具照「預先定義的程式路徑」運作S1.1
  • Agent：由 LLM 動態決定自己的流程與工具使用S1.1
  • Workflow 對定義清楚的任務較可預測、一致；agent 適合需要彈性的情境S1.3

Agent 怎麼運作？一圈一圈做

  • 核心是一個迴圈，持續運作到退出條件成立S2.7
  • 經典樣式 ReAct：Thought → Action → Observation，重複多輪S3.3
  • 每一步都要向環境取得 ground truth（例如工具結果）來判斷進度S1.6
  • 停下來的條件：完成、出錯、或達到最大回合數S2.7

三個核心零件：規劃、記憶、工具

  • 規劃：把大任務拆成小步驟（例如 Chain of Thought）S3.2
  • 記憶：短期記憶受 context window 限制；長期記憶放在外部向量資料庫S3.5
  • 工具：呼叫外部 API，補足模型本身缺少的資訊S3.6
  • 工具分三類：Data（取資料）、Action（做事）、Orchestration（叫別的 agent）S2.6

怎麼確保它不走偏？護欄與檢查

  • 護欄要分層：單一護欄通常不夠，多層更穩S2.9
  • 失敗次數太多、或高風險動作，就交給人類S2.10
  • 先在沙盒中大量測試，再放手S1.8
  • 小心：LLM 自己評估自己可能不可靠（ChemCrow 案例）S3.9

Agent 能做什麼？

  • 客服：預判需求、主動處理，必要時轉給真人S5.5
  • 寫程式：探索程式碼庫、找相關檔案、跑測試S5.9
  • 法律：據報導，文件審閱、研究與起草時間平均減少約三分之一S5.8
  • 金融：持續偵測詐欺、監控合規S5.6

注意：效益數字多為廠商或客戶自述，未經獨立驗證。

什麼時候「不該」用 Agent？

  • 先用最簡單的解法，有時根本不需要 agentS1.3
  • Agent 常以延遲與成本換取更好的表現S1.3
  • 適合的場景：複雜決策、規則難維護、大量非結構化資料S2.4
  • 目前限制：context 有限、長期規劃困難、自然語言介面不夠可靠S3.10

三句話帶走

  • Agent ＝ 用 LLM 做決策、用工具行動，並在迴圈中一步步完成任務S2.3S2.7
  • 三個零件：規劃、記憶、工具S3.1
  • 放手之前，先設好護欄、留好人類介入的出口S2.9S2.10
