# Agent 與聊天機器人、Workflow 的差別

## 與聊天機器人

| 面向 | 傳統聊天機器人 | Agent |
|---|---|---|
| 回應方式 | 依預設腳本回應 [S5.5] | 能預判需求並主動採取行動 [S5.5] |
| 誰控制流程 | 不用 LLM 控制工作流程，不算 agent [S2.2] | 用 LLM 管理工作流程並做決策 [S2.3] |
| 資料來源 | 受限於訓練資料與當輪輸入 | 可呼叫工具與 API，突破訓練資料限制 [S5.3] |
| 記憶 | 通常以單一任務運作 [S5.2] | 會跨互動儲存記憶 [S5.3] |
| 遇到困難 | 照腳本回覆 | 複雜問題會升級給人類，或直接開工單、處理退款 [S5.5] |

## 與 Workflow（容易混淆）

- Workflow：LLM 與工具透過「預先定義的程式路徑」被編排 [S1.1]。
- Agent：LLM 自己動態決定流程與工具使用 [S1.1]。
- Workflow 對定義清楚的任務較可預測、一致；agent 適合需要彈性與模型自行決策的大規模情境 [S1.3]。

## 什麼時候不該用 Agent

- Anthropic 建議先用最簡單的解法，有時根本不需要 agentic 系統，因為 agentic 系統常以延遲與成本換取更好的表現 [S1.3]。
- OpenAI 建議只有在複雜決策、難維護的規則、或大量非結構化資料這三類場景才優先考慮 agent，否則確定性方案可能就夠 [S2.4]。
