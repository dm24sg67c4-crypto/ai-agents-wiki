## 要點（引用時請用編號，例如 [S3.2]）

- **S3.1** 在 LLM 驅動的自主 agent 系統中，LLM 扮演大腦，搭配三個關鍵元件：規劃（Planning）、記憶（Memory）、工具使用（Tool use）。
- **S3.2** 規劃包含任務分解與自我反思。任務分解常見做法有 Chain of Thought（要求模型逐步思考）、Tree of Thoughts（每一步探索多種想法形成樹狀）、以及 LLM+P（把長期規劃外包給傳統規劃器）。
- **S3.3** 自我反思讓 agent 能回顧過去的行動、修正錯誤，在必然會試誤的真實任務中很重要。ReAct 把推理與行動結合，提示格式大致是 Thought、Action、Observation 重複許多輪；Reflexion 則為 agent 加上動態記憶與自我反思，產生的反思會被加進 agent 的工作記憶（最多三則），作為後續詢問 LLM 的脈絡。
- **S3.4** Reflexion 用一個啟發式函數判斷何時軌跡低效或出現幻覺，其中幻覺的定義是連續出現相同動作卻得到相同觀察。
- **S3.5** 記憶分短期與長期：短期記憶對應 in-context learning，受限於 Transformer 有限的 context window；長期記憶對應外部向量資料庫，透過快速檢索（近似最近鄰搜尋）取用。
- **S3.6** 工具使用是讓 agent 呼叫外部 API，補足模型權重中缺少的資訊，例如最新資訊、執行程式的能力、私有資料來源。
- **S3.7** MRKL 架構讓 LLM 當路由器，把請求分派給最適合的專家模組；文中也提到 Toolformer、TALM，以及 function calling 與外掛等實際例子。
- **S3.8** 實驗顯示「知道何時以及如何使用工具」很關鍵，這取決於 LLM 本身能力，例如較小模型在文字題的算術上很難可靠地抽出正確參數。
- **S3.9** ChemCrow 案例中，LLM 自我評估認為 GPT-4 與 ChemCrow 表現差不多，但專家人工評估發現 ChemCrow 大幅領先，作者據此指出：在需要深度專業的領域，用 LLM 評估自己的表現可能有問題，因為它可能不知道自己的缺陷。
- **S3.10** 作者列出三項常見限制：有限的 context 長度（向量檢索雖能存取更大的知識池，但表達能力不如完整的注意力機制）；長期規劃與任務分解困難，遇到意外錯誤時不易調整計畫；自然語言介面不夠可靠（格式錯誤、偶爾不遵從指令），所以許多 demo 程式碼都在解析模型輸出。
- **S3.11** 案例包括 ChemCrow、Generative Agents（25 個虛擬角色的模擬）、AutoGPT 與 GPT-Engineer 等概念驗證。

## 可信度備註

2023 年中的整理，概念框架（規劃、記憶、工具）到現在仍被廣泛引用，但具體技術與模型能力已有大幅進展，引用細節時需注意年代。
